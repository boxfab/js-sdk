# Upstream

The BoxFab JavaScript SDK is derived from the open-source
[E2B JavaScript SDK](https://github.com/e2b-dev/E2B/tree/main/packages/js-sdk) (MIT) and includes
modifications for BoxFab's sandbox infrastructure. BoxFab is an independent project and is not
affiliated with or endorsed by E2B.

## Pinned source

- Repository: https://github.com/e2b-dev/E2B
- Path: `packages/js-sdk`
- Release: `e2b` 2.61.0 (tag `e2b@2.61.0`)
- Commit: `ee355b765ac0e884fbeaa69e4b44f4c7c58ed6b1`

2.61.0 is the SDK release that `@boxfab/cli` 0.1.0-alpha.1 bundles, so the CLI and this package
run the same SDK code.

## How the code is produced

`src/`, `tests/` and `CHANGELOG-E2B.md` are generated by `scripts/sync_upstream.py`
from the pinned commit and are never edited by hand. The build configs (`tsconfig.json`,
`tsdown.config.ts`, `vitest.config.mts`) are this repository's own: upstream's extend shared
monorepo files, whose settings they inline. The script copies the upstream package and applies a
fixed, asserted set of rewrites:

| Change | Why |
|---|---|
| every `E2B_*` variable the SDK reads → `BOXFAB_*` (`API_KEY`, `DOMAIN`, `API_URL`, `SANDBOX_URL`, `DEBUG`, `HTTP_VERSION`, `API_CONNECTIONS`, `ENVD_RPC_CONNECTIONS`, `VOLUME_API_URL`), no fallback | a BoxFab install never picks up an E2B key or domain, nor sends a key to E2B's service |
| default domain `e2b.app` → `boxfab.io` (API and volume clients, doc comments) | BoxFab's domain; no implicit calls to E2B's service |
| client class `E2B` → `BoxFab`, `E2BClientOpts` → `BoxFabClientOpts`; the old names stay exported as aliases | branding; existing code ports by changing the import |
| User-Agent `boxfab-js-sdk/<ver>`, `publisher: boxfab` header | identifies the SDK to the BoxFab API |
| missing-key error points to the BoxFab dashboard and `BOXFAB_API_KEY`; docs link `boxfab.dev/docs`; one template error names the BoxFab API | actionable messages |
| product name in doc comments `E2B` → `BoxFab` (31 lines, asserted; lines with URLs and three comments about E2B's own hosted service are left alone) | the declarations users read in their editor name the product they talk to |
| tests: the same variable renames; tests of the default domain expect `boxfab.io`; `tests/boxfab-env.setup.ts` (overlay) refuses to run against an E2B domain; `tests/runtimes/` (browser, Workers, Bun, Deno smoke suites) removed | tests exercise BoxFab only |

Deliberately unchanged:

- The list of E2B-hosted domains in `src/connectionConfig.ts`. For those domains the SDK sends
  sandbox traffic to a shared `sandbox.<domain>` host; for any other domain (ours) it uses
  `https://<port>-<sandboxID>.<domain>`, which is what BoxFab serves.
- Shell variables inside generated template build steps (`E2B_HEREDOC_*`), wire-level identifiers
  (headers such as `E2b-Sandbox-Id`, the `e2b_` API-key prefix, generated API and envd clients),
  the default template base image `e2bdev/base`, and the MCP server schema's `e2b` entry: they are
  protocol or third-party names, not branding.
- The dependency `@e2b/dockerfile-utils` (published on npm by E2B) is used as is.

## Desktop package (`desktop/`, `@boxfab/desktop`)

Generated in the same sync run, from the same monorepo commit, by `scripts/sync_desktop.py`:
`packages/desktop-js` (`@e2b/desktop` 2.5.0 at that commit) → `desktop/src`, `desktop/tests`
(without the Cloudflare Workers suite), `desktop/CHANGELOG-E2B.md`, and `desktop/README.md` (our
introduction from `scripts/desktop/`, then upstream's README from "3. Create Desktop Sandbox" on).
`desktop/package.json`, the build and test configs and `desktop/CHANGELOG.md` are this repository's
own; `desktop/LICENSE` is a copy of `LICENSE`.

| Change | Why |
|---|---|
| imports of `e2b` → `boxfab` | the core SDK is `boxfab` |
| `E2B_*` variables read by the package and its tests → `BOXFAB_*` | as in the core SDK |
| client class `E2B` → `BoxFab`, `E2BClientOpts` → `BoxFabClientOpts` (old names exported as aliases) | as in the core SDK |
| live tests take the template from `BOXFAB_DESKTOP_TEMPLATE` (default: the SDK's `desktop`) | test a template build before it becomes the default |

The desktop sandbox template itself is in [boxfab/desktop](https://github.com/boxfab/desktop)
(generated from `e2b-dev/desktop`).

## Updating to a newer upstream release

1. Set `UPSTREAM_TAG` / `UPSTREAM_COMMIT` (the commit the tag points to, `git rev-parse
   '<tag>^{commit}'`) in `scripts/sync_upstream.py`, and the dependencies in `package.json` to that
   release's.
2. `python3 scripts/sync_upstream.py`; fix any rule whose count no longer matches.
3. `npm ci && npm run build && npm test`, then `BOXFAB_API_KEY=… npm run test:live`.
4. Update this file and `CHANGELOG.md`.
